1 · Types

Two types: who runs the code

Every extension is either hosted or standalone. That is the only type switch in the manifest (execution). Two more choices shape each extension: who connects the account, and what starts its code.

Retainer never calls into a standalone app. The app calls Retainer, the same way an outside service would.

2 · Hosted: big picture

Three zones. Extension code runs in the middle one.

The rest of this page is about hosted extensions. Retainer's server never runs their code itself. The coordinator invokes it in a sandbox (a Lambda version hosted, a fresh container self-hosted) with two short-lived tokens: one for the API, one for the model proxy.

Edge cases

  • No configure in the release: approvals 1 and 2 merge into one.
  • Enrichment's configure: checks the Exa key, samples the 20 latest companies, asks the model for a field (or Create / Skip) per output. Falls back to name and type matching.
  • Suggestions pass resolveMapping before the form shows them.
  • Admin can Skip suggestions or Continue later. The card shows "Waiting for your review".
  • Unfinished after 14 days: cancelled, secrets deleted. Suggesting again doesn't reset the clock.
  • Editing the mapping later runs no setup or backfill.

4 · Runtime

One enrichment run

The extension uses the normal Anthropic SDK, pointed at Retainer's proxy with a model token as its key. The proxy swaps in our key, streams the reply back and records usage. The extension chooses the model, prompt, tools and data.

Exactly one result on the record's domain? Enrichment takes it without a model call (matched_shortcut).

Extension code

import { modelClient } from '@retainer/extension';

const anthropic = modelClient(invocation);
const pick = await anthropic.messages.create({
  model: 'claude-opus-5-5',
  max_tokens: 4000,
  messages: [{ role: 'user', content: prompt }],
});

modelClient sets the proxy URL, the model token and a timeout from the run's deadline. It throws if the run has no model access.

Two tokens, separate doors

Run tokenModel token
Retainer API●○
Model proxy○●
Expiresat the run's deadline, ≤ 5 min

The model token is minted only for functions that declare uses: ['model'] on a granted installation. The proxy is public when hosted, so it never holds a credential that opens a workspace. A cancelled run's token works until expiry: it can cost tokens, never data.

Inside a run, code can

  • Use any TypeScript and bundled npm package
  • Call any public address (self-host: egress proxy blocks private ones)
  • Read its own secrets (sdk.extensionSecret)
  • Call the model, if declared and granted
  • Run a full agent loop, each turn through the proxy
  • Queue child jobs and keep progress in installation KV
  • Return JSON output on success, within the result's 64 KiB (section 5)

It can't

  • See our model key
  • Run past 300 s (120 s default), model calls included
  • Read records from install, only from configure and runs
  • Use Managed Agents, Files, Batches or Skills: they keep state in our Anthropic account
  • Touch the database directly

Where it runs when hosted

api has no route to the internet, so the proxy is its own model function. Anything that reads outside content stays outside the VPC and reaches data only through api.

  • Checks the model token's signature without the database. Reports usage to api: 3 tries, then the call goes uncounted and is logged.
  • Streams through a function URL with reserved concurrency. Skips the NAT gateway.
  • A function URL can't tell when the caller leaves, so an abandoned call runs to max_tokens and is recorded whole (staging, 2026-11-14).
  • Self-hosted: the same module in the server process, writing ai_usage directly.
5 · Tools

A tool is a function others call, and it returns data

A tool is extension code with the new tool trigger, such as "is this address deliverable" or "send a WhatsApp message". A routine, a person's button or, later, an agent calls it with typed input and gets typed output back. It runs in its own job with its extension's credentials, so the caller never holds them. Like any function, it can declare uses: ['model'].

Declaring a tool

import { defineTool } from '@retainer/extension';

export const checkAddress = defineTool({
  universalId, handlerDigest,
  name: 'check_address',
  title: 'Check an address',
  description: 'Checks whether an address is deliverable.',
  effect: 'read',
  connection: 'workspace', // must match the release
  inputSchema: {
    type: 'object',
    properties: { address: { type: 'string' } },
    required: ['address'],
    additionalProperties: false,
  },
  outputSchema: {
    type: 'object',
    properties: { deliverable: { type: 'boolean' } },
    required: ['deliverable'],
    additionalProperties: false,
  },
});

defineTool folds title, effect, connection and outputSchema into the trigger: { kind: 'tool', … }.

What the manifest checks today

  • Tool names are snake_case: a lowercase letter, then up to 99 of a-z 0-9 _
  • outputSchema uses the same bounded JSON Schema subset as inputs: no refs, objects reject extra properties
  • Any schema node may carry a description (≤ 2,000 chars), written for an agent
  • defineExtension refuses a tool whose connection differs from the release's
  • The result's output is any JSON, only on succeeded, and the whole result stays ≤ 64 KiB
{ status: 'succeeded', output: { deliverable: false } }

Still protocol v1, as when the invocation gained model. Every bundle is rebuilt with the updated schema.

The effect decides where a tool may run

read Runs in test runs

Answers a question for a routine's condition. Must not write or act outside.

write Runs in test runs

Changes Retainer records only. Its writes can't trigger the routine that called it.

send Blocked in test runs

Acts outside Retainer. Delivery is at least once, so it uses the call's key to avoid sending twice.

A routine dry run blocks every tool. Retainer trusts the declared effect: tool code keeps its extension's credentials and network access.

  • Polling, not waiting: a tool may run 120 s, and the hosted API answers within 30 s. The routine SDK hides it: retainer.tools.<name>(input).
  • A member tool runs only when a person starts it, with their own connection, checked again when the queued call runs.
  • Hosted today, extensionServices lists no tool kind, and an unlisted kind stops the catalog loading (the 2026-11-15 connect outage). The server change ships before any hosted bundle with a tool.
6 · Future goal

Extensions hand tasks to the workspace's agent

Retainer gets its own agent with a prompt, memory, model choice, Retainer's tools and people's connections. An extension gives it a task and gets an answer back. It never sees the Gmail tokens.

Amber: the only new piece. Everything else exists today.

RULE 1

Harness from the agent, authority from the run

Its Retainer actions use the run's access (read-only in configure) and are recorded as the extension's. Already the rule for anything Retainer runs on a run's behalf.

RULE 2

Workspace agent, or a member's

Runs are workspace-level and can't read personal memory. A member's agent with their Gmail needs that member to connect it.

RULE 3

Tasks are asynchronous

Start a task and end; a child job resumes with the answer. No 300 s limit for agent work.

Extension code, later (illustrative)

// run 1: hand the decision to the workspace's agent
await agentClient(invocation).start({
  task: 'Which of these search results is this company, if any?',
  input: { company, results },
  output: pickSchema,
  resume: 'apply-pick',   // job to run when the answer is ready
});

// run 2 (child job 'apply-pick')
const { answer } = invocation.input;

Why this way

  • Self-host runs the same code: same queue, same worker
  • Retries, leases and fencing already exist for jobs
  • Isolation and run access stay inside Retainer
  • Retainer is the memory; Mastra's memory and storage stay unused
  • Gmail tokens arrive through the secret broker, like extension secrets

What it costs

  • A few runtime endpoints (claim a step, save state)
  • An HTTP round trip per step
  • A task token that works from anywhere until it expires
  • Outbound calls from outside the VPC can't be restricted or logged
  • Mastra: Apache-2.0 core only. Paid ee/ (RBAC, Agent Builder, Studio SSO) stays off; configuring it without a key stops the server
