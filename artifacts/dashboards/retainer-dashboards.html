Dashboards

Ask the agent for a dashboard in plain words. It draws one live in the chat, and you pin it to keep it. A core feature, beside views and Routines.

1 · At a glance

The agent writes it once. After that, no model is involved.

Always current

A dashboard stores no numbers. Its queries run each time it opens.

Your own access

Queries run as the viewer. Two people can see different numbers on the same dashboard.

The person saves

The agent never saves a dashboard. A dashboard only reads; it has no buttons that change data.

2 · A short program

A dashboard is a few lines that say what to show and what to ask

What the agent writes

root = Dashboard("Deals", [kpis, stages, open])

// what to ask
openDeals = Query("aggregate_records", {
  object: "deal", filter: {stage: {in: […]}},
  aggregates: [{field: "amount", op: "sum",
                as: "pipeline"}]})
byStage = Query("aggregate_records", {
  object: "deal", groupBy: "stage",
  aggregates: [{field: "amount", op: "sum",
                as: "amount"}]})
top = Query("query_records", {
  object: "deal", limit: 3, sort: […],
  fields: {stage: "stage", amount: "amount"}})

// what to show
kpis = Row([count, pipeline])
count = Metric("Open deals", openDeals.total)
pipeline = Metric("Open pipeline",
  openDeals.values.pipeline)
stages = BarChart("Amount by stage",
  byStage.groups.label, byStage.groups.amount)
open = Table("Biggest open deals",
  top.records, […])

4 · The agent

It learns the language only when asked, and checks its work before answering

  1. 1

    Told once

    In a web chat, one line in the first message says dashboards can be shown here.

  2. 2

    Reads the guide

    get_guide("dashboards"), about 4,000 tokens, only when a dashboard is asked for.

  3. 3

    Learns, then tries

    describe_schema, then the real queries with aggregate_records.

  4. 4

    Checks

    check_dashboard returns the problems, and the agent fixes them.

  5. 5

    Answers

    A sentence and the program. The chat draws it.

5 · Components

A fixed list of parts, shared by the agent's guide and the web app

RowTiles side by side
MetricOne headline number
BarChartValues across categories
StackedBarCategories split in two ways
LineChartValues over time
PieChartShares of a whole
TableRecords, up to 100 rows
TextA short note

The list lives in one place. The guide the agent reads and the parts the browser draws are both built from it, so they can't drift apart. An unknown part is dropped and reported, never drawn.

10 · Limits and safety

Read-only by construction

20 KBprogram size
20queries per dashboard
≥ 60 sbetween refreshes
200rows per query
100rows shown in a table
50–200groups per aggregate
7pie slices
  • It can only read. The browser gives a program two read functions and nothing else.
  • It runs as the viewer. A query the viewer can't run fails in its own tile.
  • It is data, not code. Nothing in a program is executed as script.
  • Nothing leaves Retainer. Built in-house on OpenUI's open-source parts; no outside service.
