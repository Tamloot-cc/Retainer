# Review changes and manage access

## Review what an agent wrote

Open **Review inbox** in the workspace. For a proposed field value, compare it
with the current value on the record and inspect the source when one is attached.
Choose **Accept** or **Reject**. Acceptance records your decision. If a newer
value took precedence while you were reviewing, the inbox tells you which value
remains current.

The inbox also groups proposed schema changes, possible duplicates, and
unresolved event participants. Review a duplicate suggestion before merging:
the selected record survives and receives the relevant history from the other
record. A workspace admin can approve or reject proposed schema changes.

## Manage people and agents

In accounts mode, open **Settings → Members** to check who has access to the
workspace. Viewers can read, editors can also write and review, and workspace
admins manage roles, agents, and schema changes. A workspace admin can add
existing organization members. An organization owner or admin invites new
people.

Use **Settings → Agents** to create or revoke workspace API keys and manage
connected apps. Give each agent a separate key with the scopes it needs. A
person can also manage their own OAuth connections under **Your account**.

For instances that use keys for sign-in, see
[Workspaces and API keys](../self-hosting.md#workspaces-and-api-keys).
